# First BetterMate hardware test

The LilyGo T-RGB display was flashed over `/dev/cu.usbmodem2101` with the current
BetterMate display firmware and its embedded web UI. The display is powered by USB
and connects to the machine over Bluetooth.

## Verified

- Upload completed with flash hash verification. The existing partition table
  matches the build. NVS settings and LittleFS were outside the erased regions.
- The RGB panel, CST820 touch controller, and PSRAM initialize successfully.
  The user confirmed BetterMate is visible on the round display.
- Saved Wi-Fi settings reconnect successfully. Web UI: `http://192.168.1.142/`.
- All 53 web assets served by the physical display match the local embedded
  bundle byte for byte after decompression. REST status and WebSocket streaming
  work. All five saved profiles are readable; Adaptive v2 remains selected.
- The display connects to GaggiMate Pro Rev 1.0 running stock `v1.9.0`.
  System status becomes `ready`, with no protocol mismatch. Live temperature,
  pressure, Bluetooth RSSI, and latency arrive from the controller.
- User interaction changed Standby to Brew, selected a 93 °C target, and returned
  to Standby. A subsequent test reached approximately 67 °C before returning
  to Standby; temperature decreased afterward.
- The user held the Brew screen's play button for a short touch flush and
  confirmed water flow and pump stop on release. Subsequent telemetry reports
  Standby, no active process, and pump power zero.
- Simulator startup, all themes, wake/return, clock/rest/drift, and wake guards
  passed all 43 assertions after the startup fix.

## Fixes found during the test

1. `DefaultUI` started a stock fade with automatic deletion before the derived
   BetterMate UI loaded its screen. On hardware, replacing the still-running
   fade deleted its active screen and caused a null dereference in
   `lv_obj_get_local_style_prop`. The base screen now loads synchronously for the
   derived UI; direct `DefaultUI` construction retains its startup fade.
2. SCons did not track the web blob referenced by the assembler's `.incbin`.
   A cached object contained an older blob alongside the current manifest,
   producing incorrect assets and gzip errors. `embed_webui_pre.py` now declares
   the blob as a dependency of its assembly object. The resulting firmware
   contains all 541,922 bytes of the current bundle, verified locally and on USB
   hardware over HTTP.

`lib/NanoPbComm/` and controller firmware were not modified or flashed.

## Local evidence and recovery

The private backup and logs are outside the firmware repository, in the
workspace directory alongside `bettermate/`:

`hardware-backups/display-80b54ec7e718-20261003/`

- `pre-bettermate-full-flash.bin`: original 16 MiB flash backup.
- `backup-metadata.json`: backup SHA-256 and partition layout.
- `flashed-*` and `flashed-build.json`: final flashed binaries, ELF, and hashes.
- `bettermate-boot.log`: original BetterMate startup crash.
- `bettermate-fixed-boot.log`, `bettermate-final-boot.log`: successful startup logs.
- `upload-final.log`: final upload and hash verification.
- `device-verification.json`: all asset checks, profiles, and WebSocket snapshot.
- `machine-connection.json`, `machine-connected.json`: actual controller telemetry.
- `machine-flush.json`, `machine-flush-followup.json`: telemetry around the
  user-confirmed flush test and final Standby state. The brief pump activation
  occurred between capture windows; water flow and release-to-stop are the
  user's physical observations.

Simulator captures and logs: `/tmp/bettermate-hardware-standby-20261003/`.

The backup contains existing device settings and stays local. Steam, an actual
espresso shot, scale integration, and long-duration hardware operation remain
outside this first smoke test.

Stock controller telemetry has one caveat: `Heater::getDutyCycle()` reports its
stored PID output even in Standby. `Heater::loop()` sets the GPIO low for a zero
setpoint without clearing that output, so `hp` can remain at the last heating
percentage after returning to Standby. This was observed while temperature
decreased; the controller implementation was left unchanged.
