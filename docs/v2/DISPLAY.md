# Display v2 — how the UI is built and how to write a screen

Read `design/reference/round-display.md` and `design/reference/motion.md` first: they say what each screen shows and
what may move. `design/reference/components/bundle.js` (`var screens`) draws every screen with exact coordinates; treat
it as the layout source. This file says how those become code under `src/display/ui/bettermate/`.

## The shape of it

- **One LVGL screen.** `BetterMateUI` owns it. Nothing is ever loaded with `lv_scr_load`: a screen change repaints only
  the parts that come and go. The stock UI, EEZ and the LVGL default theme are gone, and so are flex, arcs, meters and
  every widget but `lv_obj`, `lv_label`, `lv_img`, `lv_canvas` and `lv_qrcode` (`src/display/lv_conf.h`).
- **The ring belongs to the UI** (`TickRing`). A screen says what it should carry from `update()`
  (`host.ring().show(...)`, `pulse()`, `busy()`); the ring walks there a few ticks a frame and stays put through a
  screen change. One tick is a 26 px box, 0.3% of the panel.
- **Frames, not milliseconds** (`Motion.h`). The UI advances one frame every 42.5 ms, the panel's scan. Per frame:
  step-ins and presses advance, the machine is snapshotted when due (every 6th frame, or at once when an event marks the
  UI dirty), the active screen's `update()` runs on a new snapshot and its `tick()` runs every frame, the ring steps,
  and LVGL repaints what changed, once (`_lv_disp_refr_timer`; LVGL's own refresh timer is deleted).
- **A screen is a set of parts on the root**, each with a rank: 0 label and reading, 1 second-rank values, 2 action
  and handle. On a change the old screen gives up one rank a frame while the new one takes it (`Screen::conceal`,
  `reveal`), then the ring walks. Only a `Reading` steps in by recolour during the settle; everything else arrives with
  the cut. The host measures each step: when the outgoing and the incoming rank together would repaint more than 22%
  of the panel, the incoming rank waits one frame, so the 25% limit holds for any pair of screens. Measured in the
  simulator: 20 to 23% of the panel in the largest frame, about 3% a frame while the ring walks.
- **One design, two panel sizes.** Every position is in the design's 480 px box. `ui::root()` is that box, a stage
  centred on the LVGL screen: on the 466 px AMOLED boards it starts 7 px outside the glass on every side. Only the
  ring reaches that far, so there its ticks end 7 px sooner (212 to 227 instead of 234) and keep their 3 px to the
  edge; nothing else changes. A part that draws itself (`TickRing`, `StageBars`, `Reading`) adds its object's
  position to what it draws and repaints: the stage is not at 0, 0 on every panel. The step budget is 22% of the
  panel that is there.
- **Exact repaints.** LVGL 8.4 grows every area an object invalidates by 5 px a side. `ui::` setters and `ui::show`
  switch that off and invalidate the object's own box (`ui::invalidate`). Use them; do not call `lv_obj_invalidate`,
  `lv_obj_add_flag(.., HIDDEN)` or `lv_obj_set_style_*_color` on a part yourself.
  A screen's parts are built with invalidation off (`Screen::enter`): a new label is visible at the stage's origin
  until `part()` hides it, without a size but with the margin LVGL keeps around a label (a quarter of its line
  height), and every style set on it would mark that margin for repainting, 11 x 11 px at 0, 0.

## Files

| File | What |
| --- | --- |
| `gen/` | Generated by `scripts/design/gen_display_assets.py`: `bm_tokens.h` (two palettes, sizes, ring, frames, tracking), seven fonts, icons as 8-bit alpha maps. Add an icon by adding it to `ICONS` there and regenerating (needs `fonttools`, `brotli`, Pillow, `rsvg-convert`, Node). |
| `Theme.h` | `Tone` (the color tokens), `Type` (the seven type styles), `tone(t)`, `tone(t, level)`, `font`, `tracking`, `ascent`. Display black is the default theme on every panel; Light is a setting. |
| `Motion.h` | Frame counts and the ease tables. |
| `TickRing.h` | The ring: `Layout::{None, Split, Single}`, `Arc{value, target, tone, pace}`, fixed scales `MAX_TEMPERATURE` 160 and `MAX_PRESSURE` 16. |
| `Ui.h` | The parts: `text`, `textLeft`, `fit`, `clamp`, `icon`, `pill`, `disc`, `textButton`, `labelButton`, `group`, `card`, `chip`, `SegRow`, `Reading`, and `setText`, `setTone`, `setFill`, `setPill`, `setIcon`, `show`, `pressable`, `invalidate`. |
| `parts/` | Custom-drawn parts one screen needs: `StageBars` (the phases of a shot, growing a pixel at a time). |

| `UiState.h` | The snapshot a screen reads. A screen never reads the controller. |
| `BetterMateUI.*` | The host: events, snapshot, routing, intents, frames, theme, brightness, favourites task. |
| `screens/` | One class per screen: Standby, Brew, Shot, Mode (Steam, Water, Grind), Menu, Profiles, Adjust, Sheet, Warnings, Info. |

## Writing a screen

```cpp
void BrewScreen::build(lv_obj_t *root) {             // once; every object put on root is a part
    addException();                                    // 12 o'clock slot, rank 0
    label = part(ui::text(root, 240, 98, Type::Label, Tone::Muted, "BREW", 216), 0);   // centre x, baseline y
    temperature.build(root, 240, 222, Type::Hero, Tone::Ink);                           // a Reading
    part(temperature.obj(), 0);
    start = part(ui::pill(root, 240, 334, 188, "START", Tone::Primary), 2);
    bind(start, Intent::Start);                        // SHORT_CLICKED unless another event is given
    addHandle();                                       // 6 o'clock chevron, opens the menu, rank 2
}
void BrewScreen::update(const UiState &s) {           // on every snapshot: say everything, change nothing twice
    host.ring().show(TickRing::Layout::Split, {tempFraction, targetFraction, Tone::Heat}, {pressureFraction, -1, Tone::Primary});
    ui::setText(label, heating ? "HEATING TO 93°" : "BREW");
    ui::setTone(label, heating ? Tone::HeatText : Tone::Muted);
    temperature.set("93");
    show(start, s.canWake);                            // rule 4: a control that cannot be used is hidden
}
```

Rules that keep it cheap and correct:

1. Positions are panel pixels from the design, text by its **baseline**. No flex, no `lv_obj_align` chains, no
   full-panel containers (showing one repaints the panel).
2. Everything created directly on `root` is registered with `part(obj, rank)`. Children of a part follow it.
3. Change a part only through `ui::setText/setTone/setFill/setPill/setIcon` and `Screen::show` (or `ui::show` for a
   child). They skip unchanged values and repaint exactly. `update()` is called 4 times a second: it must be idempotent
   and must not move or resize anything unless the value behind it changed.
4. Give a changing label a fixed width sized for its longest value. Use a `Reading` for any numeral in `Hero`,
   `HeroSm` or `Value` that changes: it repaints only the digit cells that changed.
5. Never: style opacity, `transform_*`, `translate_*`, `lv_anim`, scrolling containers, images larger than an icon,
   a second color for the same meaning. A fade is `tone(t, level)` through `ui::show(obj, true)`; a leave is a cut.
6. Motion between snapshots (a timer, a growing bar) goes in `tick(state, frame)`, counted in frames, repainting only
   what moved. One ambient motion at a time: the ring's pulse or its comet.
7. A name that may be too long is cut with `ui::fit` or kept on a `ui::clamp`ed label; never LVGL's dot mode, which
   rewrites the label's text so that an unchanged name looks changed on every snapshot. The label face has capitals, digits and punctuation only; the button face has `A-Z`, space and `&`. Uppercase any
   name you put in them with `upper()`. The hero faces have digits, `:`, `.`, `-`, space and `°`.
8. Units: a large reading carries a small unit label under it; small text writes `93°`, `9.0 BAR`, `36 G` in the label
   face and `93°`, `36 g` in the body face. Sentence case in `Body`; no state words for the normal state.
9. Touch: anything pressable is at least 56 px (`tokens::DISPLAY_TOUCH`); `ui::pill`, `disc`, `textButton`,
   `labelButton`, `group` and `SegRow` already invert to ink for two frames when pressed. A screen gets `tapped()` for a
   tap that hit no control and `swiped(direction)` for a gesture.
10. State a screen keeps to itself (which field is focused, ABOUT shown) lives in the screen; after changing it call
    `host.act(Intent::Refresh)`. Everything about the machine goes through an `Intent`.

## Budget, and how to check it

`design/reference/motion.md`: at most 25% of the panel in one step of a transition, 8% in any frame of a continuous
motion, never the whole panel. The simulator renders in a millisecond, so time proves nothing there, but the redrawn
share is exact:

```shell
pio run -e display-sim
mkdir -p /tmp/bm-run && cd /tmp/bm-run       # the sim keeps its state in ./sim_data
SIM_HTTP_PORT=8101 SDL_VIDEODRIVER=dummy <repo>/.pio/build/display-sim/program --script \
  "wait 3500; mode brew; wait 3000; redraw settle.json; shot brew.bmp; layout brew.json; quit"
# redraw <path>: one JSON line per repaint since the last redraw step: {"ms":..,"px":..}; px / 2304 is percent.
# SIM_TRACE_FLUSH=1 prints every repainted rectangle, to find out what a frame redrew.
# SIM_TRACE_INVALIDATE=1 prints every area as it is marked for repainting, and =stack the call stack with it,
# to find out which object asked.
# layout <path>: the screen, the ring (layout, lit ticks, notch, tone) and every visible object with text and colors.
```

Script verbs are listed in `sim/SimScript.h` (`mode`, `tap`, `press`/`release`, `hold`, `swipe`, `key`, `scale`,
`weight`, `pumped`, `pressure-sensor`, `controller`, `error`, `protocol`, `autotune`, `update`, `wifi`, `panel`,
`theme`, `expect ...`). The checks are `scripts/verify_display_{core,shot,modes,menu,profiles}.py`, each on
`scripts/display_sim.py`; they keep the captures under `docs/display/v2/` unless `UPDATE_SHOTS=1` is set.

The 466 px panels run the same scripts and the same checks. Points in a script and boxes in a `layout` dump are
always the design's (the simulator moves them by the stage's 7 px); only a `shot` is in panel pixels, and
`display_sim.SHOT_SHIFT` says where a design point is in it. Shares are of the 466 px panel, and the captures go to
`docs/display/v2/466/`:

```shell
for check in scripts/verify_display_*.py; do SIM_PANEL_SIZE=466 python3 "$check" || break; done
```
On hardware, `pio run -e display-frame-stats -t upload -t monitor` logs render time and redrawn share once a second.
